# Claude Code build prompt: Intelligent UI app

---

You are building **"your app"**: a desktop and web assistant whose answers are composed from a library of native, streamable UI components. The AI writes one JSON block per line (NDJSON). A server-side stream compiler validates and repairs each line. A progressive renderer draws each block, with springs, as soon as its line closes, and streams text inside blocks word by word. Interactivity (sliders, steppers) runs locally through a safe formula engine. Games and other things the catalog can't do run as generated mini-apps in a locked sandboxed iframe.

The full spec is in `./spec/Intelligent-UI-Spec.pdf` (read sections 2–14 before coding; section 7 is the notch, 8 deep research, 9 parallel tasks, 10 the company brain, 11 single-card reshaping, 12 interruptions and barge-in, 13 voice onboarding, 14 the morning burst). The machine-readable contract is `./spec/catalog.schema.json`: the line protocol, server events, and 55 components with props schemas and examples (including the Notch, Deep research, Parallel tasks, Company brain and Proactive & onboarding groups). The model's system prompt is `./spec/system-prompt.txt`. Golden streams are in `./spec/examples/*.ndjson`.

## Hard rules
- Product name is a placeholder: use `APP_NAME` from config. Do **not** copy names, branding, code, sounds or visual design from ChatGPT, Agently, or any other product.
- The model never writes HTML outside the `app` block. Everything else renders through our own components.
- Never trust model output: every line goes through the compiler (parse → repair → ajv validate with `removeAdditional: "all"` → limits → formula check) before the client sees it.
- No model-written image URLs, prices, addresses or coordinates. Use resolvers (image search, geocode) and `$ref` to tool results.
- No side effect (send, book, pay, post, delete) without an `approval` block and a user tap.
- The formula engine is `jsep` plus a whitelist interpreter. Never use `eval`, `new Function`, or member access.
- Sandbox iframe: `sandbox="allow-scripts"` only (never `allow-same-origin`), CSP `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; connect-src 'none'`, network APIs deleted by a shim, a MessageChannel bridge with `resize`, `storage.get/set`, `send` (shown as a chip; never auto-sent), `copy`, `sound`, and a 3 s heartbeat watchdog.
- TypeScript strict. Small modules. Write tests first for the compiler, formulas and store.

## Contract summary (see catalog.schema.json for the exact schemas)
Model output is either PLAIN Markdown (the first non-space character is not `{`) or NDJSON lines:
`card` (first) · `state {vars}` · `block {id,type,props,parent?,slot?}` · `patch {id,props}` · `append {id,field,text}` · `remove {id}` · `status {status,step?,say?}` · `end`.
Server → client SSE events: `line` · `tail` (provisional streamable props of the unfinished last line, ≤ every 50 ms) · `resolve` · `diag` · `text` (PLAIN mode) · `done`.
Values: literal | `{"$calc": formula, format?}` | `{"$ref": "id.field"}` | chart `data: {"$calcSeries": {x, from, to, step, y:{key: formula}}}` | `{var}` and `{result:<blockId>}` templates in button text.
Limits: card mode 12 blocks / 64 KB; full mode 40 blocks / 256 KB; 16 KB per line; at most 1 `app`.
Statuses: working · ready · needs-you · error. Timeout → error at 45 s with no new line.
The `card` line also has `surface` (`window` | `notch`) and `priority` (`needs-you` | `normal` | `quiet`).
Research and task jobs write **events** (see `research-event.schema.json`): `job · plan · step · search · source · finding · data · progress · checkpoint · report{line} · needs · error`, each with `job` and a strictly increasing `seq`. The server's canvas compiler turns events into blocks deterministically; only `report` carries model-written UI lines (which go through the normal compiler).

## Milestones (stop after each, show me, and wait for "next")
**M0. Scaffold (≤ 1 h).** Vite + React + Hono, `.env` with `ANTHROPIC_API_KEY`, `POST /api/answer` streaming Claude text over SSE with prompt caching. Accept: typing streams text into the page; the log shows cache read tokens > 0 on the second request.

**M1. Catalog and codegen.** Port `catalog.schema.json` into `catalog/components.ts` (zod). Generate the schema, prompt catalog lines and TS types. CI check: regenerated files have no diff, and every example validates. Start with these 12 components: answer, text, heading, note, list, steps, table, number, chart, buttons, control, result.

**M2. Stream compiler (tests first).** Implement section 5.2 of the spec. Tests: replay every `spec/examples/*.ndjson`; **cut-anywhere** (split each golden at every byte offset and in random chunk sizes; the final state must equal the unsplit run); fuzz (drop a quote, trailing commas, pretty-printed multi-line JSON joined by brace depth, prose lines wrapped into `text`); unknown props stripped with a `diag`; missing parent attached to root; limits enforced. Accept: 100% pass, and the compiler never throws.

**M3. Renderer and store.** Keyed blocks with `React.memo`; rAF batching; tails replace in place with no remount; PLAIN Markdown path; skeletons sized to final layout; `toMarkdown` for every component; aria roles; one polite live-region announcement when the answer block completes. Accept: the Sunday-roast golden renders progressively from a recorded stream at real timings, with no layout shift (CLS ≈ 0).

**M4. Formulas and state.** jsep plus a whitelist interpreter (numbers, declared vars, `+ - * / % ^`, comparisons, `&& || !`, `min max round floor ceil abs pow sqrt log exp if sum`). Divide-by-zero gives null and shows "—". Compile-time check that only declared vars are referenced. Property tests with 10k random expressions. Accept: the bill splitter and retirement calculator goldens work with zero network calls, and the chart updates live.

**M5. FLIP reshapes with Motion springs (interruptible, keep velocity). `prefers-reduced-motion` → 120 ms fades, no blur, no stagger, whole sentences. Local skeleton keyword rules from spec 5.3 (first match wins; under 16 ms). Status lifecycle per spec figure 4. Accept: a Playwright virtual-clock test asserts key times within ±10%; there are no long tasks over 50 ms while streaming.

**M6. Evals.** `evals/prompts.jsonl` with 30 prompts to start (10 PLAIN, 15 UI, 5 edge cases), growing to 200.
